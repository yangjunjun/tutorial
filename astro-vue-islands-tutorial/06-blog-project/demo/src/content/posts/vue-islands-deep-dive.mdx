# 深入理解 Vue Islands 架构

在现代 Web 开发中，我们常常面临一个两难选择：**性能**还是**交互性**？Astro 的 Islands 架构为我们提供了一个优雅的解决方案。

## 什么是 Islands 架构？

Islands 架构的核心思想是将页面分为两部分：

```
┌─────────────────────────────────┐
│  静态 HTML（零 JS）              │
│  ┌──────────┐                   │
│  │ 交互岛屿  │  ← Vue 组件       │
│  └──────────┘                   │
│                                 │
│  ┌──────────────────┐           │
│  │   交互岛屿        │ ← Vue    │
│  └──────────────────┘           │
└─────────────────────────────────┘
```

**静态部分**由 Astro 在构建时渲染为纯 HTML，**交互部分**（岛屿）则延迟加载 Vue 组件。

## 为什么选择 Vue？

在 Astro 中使用 Vue 作为 Islands 有几个优势：

1. **体积小**：Vue 3 的 tree-shaking 支持极好
2. **Composition API**：与 Islands 的独立组件模式天然契合
3. **渐进增强**：不需要全量加载框架

## 客户端指令详解

Astro 提供了多种客户端加载策略：

```astro
<!-- 页面加载后立即激活 -->
<SearchWidget client:load />

<!-- 浏览器空闲时加载（推荐用于非关键组件） -->
<TableOfContents client:idle />

<!-- 组件进入视口时加载 -->
<HeavyChart client:visible />

<!-- 仅在特定媒体查询匹配时加载 -->
<MobileMenu client:media="(max-width: 768px)" />

<!-- 只渲染 HTML，不发送 JS -->
<StaticBadge client:only="vue" />
```

### 选择合适的加载策略

| 组件类型 | 推荐策略 | 理由 |
|---------|---------|------|
| 搜索框 | `client:load` | 用户可能需要立即搜索 |
| 文章目录 | `client:idle` | 滚动追踪非首屏必须 |
| 暗黑模式 | `client:load` | 需尽快初始化避免闪烁 |
| 代码高亮 | `client:visible` | 只有滚动到时才需要 |
| 评论组件 | `client:visible` | 页面底部，按需加载 |

## 实战示例：计数器岛屿

下面是一个完整的 Vue Island 示例：

```vue
<!-- src/components/vue/Counter.vue -->
<script setup lang="ts">
import { ref } from 'vue';

// 从 Astro 接收 props
const props = defineProps<{
  initialCount: number;
  step: number;
}>();

const count = ref(props.initialCount);

const increment = () => {
  count.value += props.step;
};

const decrement = () => {
  count.value -= props.step;
};
</script>

<template>
  <div class="counter">
    <button @click="decrement">-</button>
    <span class="count">{{ count }}</span>
    <button @click="increment">+</button>
  </div>
</template>

<style scoped>
.counter {
  display: flex;
  align-items: center;
  gap: 1rem;
}
.count {
  font-size: 1.5rem;
  font-weight: bold;
  min-width: 3ch;
  text-align: center;
}
</style>
```

在 Astro 页面中使用：

```astro
---
import Counter from '../components/vue/Counter.vue';
---

<Counter client:load initialCount={0} step={1} />
```

## Nano Store：跨岛屿状态共享

当多个 Vue Island 需要共享状态时，Nano Store 是一个轻量级的解决方案：

```typescript
// src/stores/counter.ts
import { atom } from 'nanostores';

export const $count = atom(0);

export function increment() {
  $count.set($count.get() + 1);
}
```

```vue
<!-- 在多个岛屿中使用同一个 store -->
<script setup lang="ts">
import { useStore } from '@nanostores/vue';
import { $count, increment } from '../../stores/counter';

const count = useStore($count);
</script>

<template>
  <div>
    <p>当前计数：{{ count }}</p>
    <button @click="increment">+1</button>
  </div>
</template>
```

## 性能对比

在典型的博客场景中，Islands 架构与传统 SPA 的 JS 体积对比：

| 方案 | 首屏 JS 体积 | 首屏加载时间 |
|------|-------------|------------|
| 传统 React SPA | ~250KB | ~2.5s |
| 传统 Vue SPA | ~200KB | ~2.0s |
| Astro + Islands | ~35KB | ~0.8s |

> **结论：** Islands 架构可以将 JS 体积减少 80% 以上，同时保留必要的交互能力。

## 总结

Vue Islands 架构是构建内容优先网站的理想选择：

- **大部分页面是静态的**：博客、文档、营销页
- **少量区域需要交互**：搜索、表单、动态 UI
- **性能是核心关注点**：LCP、TTI 等指标至关重要
