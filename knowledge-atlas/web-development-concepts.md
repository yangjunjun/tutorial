# Web 开发核心概念体系

Web 开发可以理解为：浏览器通过网络访问服务端，服务端识别用户、处理业务、读写数据，再把结果返回页面。围绕这条链路，可以形成以下概念体系。

## 1. 身份、登录与权限

这是 Web 开发中最容易混淆的一组概念。

| 概念 | 含义 | 示例 |
|---|---|---|
| 身份标识 Identification | 声明“我是谁” | 用户名、邮箱、手机号 |
| 注册 Registration | 创建用户身份 | 创建账号并保存密码摘要 |
| 登录 Login | 用户提交凭证、建立登录状态 | 账号密码登录、扫码登录 |
| 认证 Authentication | 验证“你确实是谁” | 校验密码、短信验证码、指纹 |
| 鉴权 Authorization | 判断“你能做什么” | 普通用户不能删除其他用户 |
| 会话 Session | 保存用户登录状态 | Session ID、Token |
| 登出 Logout | 使当前登录状态失效 | 删除 Cookie、吊销 Token |
| 单点登录 SSO | 一次登录访问多个系统 | 企业统一登录平台 |
| 多因素认证 MFA | 使用两种以上验证因素 | 密码加短信验证码 |
| 身份联合 Federation | 信任其他身份提供方 | 使用微信、GitHub、Google 登录 |

核心区别：

```text
登录：建立登录状态
认证：确认你是谁
鉴权：确认你能做什么
```

### 常见认证方案

- Session + Cookie：服务端保存会话，浏览器保存 Session ID。
- JWT：服务端签发包含身份信息的 Token。
- Access Token + Refresh Token：短期访问令牌配合长期刷新令牌。
- OAuth 2.0：授权第三方应用访问资源。
- OpenID Connect：在 OAuth 2.0 之上增加身份认证。
- API Key：通常用于程序或服务身份，不适合普通用户登录。
- Passkey / WebAuthn：使用设备密钥或生物识别进行无密码认证。

### 常见权限模型

- RBAC：基于角色，如管理员、运营、普通用户。
- ABAC：基于用户、资源、环境等属性动态判断。
- ACL：给具体资源配置具体用户权限。
- 数据权限：只能查看自己的数据、所属部门数据或指定范围数据。
- 多租户权限：不同企业或租户之间的数据必须隔离。

## 2. 浏览器与页面基础

### HTML

HTML 描述页面结构，例如：

- 标题、段落；
- 表单、输入框；
- 图片、视频；
- 表格；
- 语义化标签。

### CSS

CSS 控制页面表现：

- 布局；
- 颜色；
- 字体；
- 动画；
- 响应式适配；
- 深色模式。

常见布局机制包括：

- 普通文档流；
- Flexbox；
- Grid；
- 定位；
- 层叠上下文和 `z-index`。

### JavaScript

JavaScript 控制页面逻辑：

- 响应点击和输入；
- 请求后端接口；
- 操作页面内容；
- 管理状态；
- 执行业务规则。

### DOM

浏览器将 HTML 转换成的对象树。JavaScript 通过 DOM 查询和修改页面元素。

### BOM

浏览器提供的页面之外的能力，例如：

- `window`；
- 地址栏和路由；
- 浏览历史；
- 屏幕尺寸；
- 定时器。

### Web Components

浏览器原生组件化机制，包括 Custom Elements、Shadow DOM 等。

## 3. 前端应用架构

### 组件化

把页面拆成可以复用和组合的组件：

```text
页面
├── 导航栏
├── 搜索表单
├── 数据表格
└── 分页器
```

### 状态管理

状态是影响页面显示的数据，通常分为：

- 本地状态：弹窗是否打开、输入框内容；
- 页面状态：筛选条件、当前页码；
- 全局状态：当前用户、主题、购物车；
- 服务端状态：接口查询结果、缓存、加载状态。

### 路由

根据 URL 展示不同页面：

- 前端路由：SPA 内部切换页面，不重新加载整个文档；
- 后端路由：服务端根据 URL 返回不同内容；
- 动态路由：如 `/users/:id`；
- 路由守卫：进入页面前判断是否登录或有权限。

### 生命周期

组件从创建到销毁会经历不同阶段，例如：

- 创建；
- 挂载；
- 更新；
- 卸载。

### 数据绑定

让数据变化自动反映到页面：

- 单向数据流；
- 双向绑定；
- 响应式数据。

### CSR、SSR、SSG 与 ISR

| 模式 | 含义 | 特点 |
|---|---|---|
| CSR | 浏览器渲染 | 交互灵活，首屏依赖 JavaScript |
| SSR | 服务端实时生成 HTML | 首屏和 SEO 较好 |
| SSG | 构建时生成 HTML | 访问快，适合内容站 |
| ISR | 按周期增量更新静态页面 | 兼顾静态性能和内容更新 |

## 4. HTTP 与网络通信

### HTTP 请求与响应

一次请求通常包含：

- URL；
- HTTP 方法；
- Header；
- Cookie；
- 请求体 Body。

响应通常包含：

- 状态码；
- Header；
- 响应体。

### HTTP 方法

- `GET`：查询资源。
- `POST`：创建资源或触发操作。
- `PUT`：整体替换资源。
- `PATCH`：部分修改资源。
- `DELETE`：删除资源。

### HTTP 状态码

- `200`：成功。
- `201`：创建成功。
- `204`：成功但没有响应内容。
- `400`：请求参数错误。
- `401`：没有通过认证。
- `403`：已经识别身份，但没有权限。
- `404`：资源不存在。
- `409`：资源状态冲突。
- `429`：请求过于频繁。
- `500`：服务端异常。
- `502/503/504`：网关或上游服务异常。

其中：

```text
401：你还没有证明自己是谁
403：知道你是谁，但你不能执行这个操作
```

### HTTPS

HTTPS 是 HTTP 加上 TLS 加密，提供：

- 传输加密；
- 服务端身份验证；
- 数据完整性保护。

### DNS

将域名解析为 IP 地址，例如把 `example.com` 解析到服务器地址。

### 跨域与 CORS

浏览器限制网页访问不同来源的资源。来源由以下三部分共同确定：

```text
协议 + 域名 + 端口
```

CORS 是服务端明确允许某些跨域请求的机制。

### 长连接与实时通信

- 轮询：定期发起 HTTP 请求。
- 长轮询：服务端等待结果后再响应。
- SSE：服务端单向持续推送事件。
- WebSocket：客户端与服务端双向实时通信。
- WebRTC：浏览器之间进行音视频或数据传输。

## 5. API 与接口设计

### REST API

将业务对象视为资源：

```http
GET    /users
GET    /users/123
POST   /users
PATCH  /users/123
DELETE /users/123
```

### RPC

以调用操作为中心：

```text
createUser
approveOrder
cancelPayment
```

### GraphQL

客户端声明自己需要哪些字段，服务端根据查询返回数据。

### 接口契约

前后端需要明确约定：

- 请求参数；
- 字段类型；
- 是否必填；
- 响应格式；
- 错误码；
- 分页方式；
- 权限要求；
- 幂等规则。

### 参数类型

- Path 参数：`/users/123`
- Query 参数：`/users?page=1`
- Header 参数：`Authorization`
- Body 参数：JSON 或表单内容
- Cookie：浏览器自动携带的状态数据

### 分页

常见方式：

- 页码分页：`page=2&pageSize=20`
- 偏移分页：`offset=20&limit=20`
- 游标分页：`cursor=abc&limit=20`

### 幂等性

同一个请求执行多次，结果是否等同于执行一次。支付、创建订单等业务通常需要幂等键，防止重复提交。

## 6. Cookie、Session 与浏览器存储

### Cookie

浏览器随请求自动携带的小型数据，常用于保存 Session ID。

重要属性：

- `HttpOnly`：禁止 JavaScript 读取，降低凭证被 XSS 窃取的风险；
- `Secure`：只通过 HTTPS 发送；
- `SameSite`：限制跨站请求携带 Cookie；
- `Domain`、`Path`：控制生效范围；
- `Expires`、`Max-Age`：控制有效期。

### LocalStorage

- 长期保存在浏览器；
- JavaScript 可以读取；
- 不会自动随请求发送；
- 不适合保存高价值敏感凭证。

### SessionStorage

- 作用域通常是当前标签页；
- 标签页关闭后清除；
- JavaScript 可以读取。

### IndexedDB

浏览器本地结构化数据库，适合离线数据和大量缓存等场景。

### Cache Storage

常与 Service Worker 配合，用于离线访问和资源缓存。

## 7. 后端开发

### 路由与控制器

路由匹配 URL，控制器接收请求并组织响应。

### Service 业务层

保存业务规则，例如：

- 库存是否充足；
- 订单能否取消；
- 用户能否审批；
- 优惠券是否有效。

### 数据访问层

负责访问数据库或外部存储，避免业务逻辑直接拼接数据库操作。

### 中间件

在请求进入业务逻辑前后统一处理：

- 登录认证；
- 权限检查；
- 日志；
- 限流；
- CORS；
- 请求追踪；
- 异常处理。

### 依赖注入

由框架或容器负责创建和提供依赖，使业务代码更容易替换、测试和解耦。

### 定时任务和异步任务

- 定时生成报表；
- 延迟关闭订单；
- 异步发送邮件；
- 图片处理；
- 数据同步。

### 消息队列

将任务生产者和消费者解耦，常用于削峰、异步处理和事件通知。

## 8. 数据库与数据模型

### 关系型数据库

如 MySQL、PostgreSQL，核心概念包括：

- 表；
- 行；
- 列；
- 主键；
- 外键；
- 索引；
  An index is a data‑structure built on table columns, which speeds up data queries. It costs extra storage space and slows down insert, update and delete operations.
- 约束；
- Join；
- 事务。

### 非关系型数据库

- Redis：缓存、计数、分布式锁；
- MongoDB：文档存储；
- Elasticsearch：全文检索和分析；
- 对象存储：保存图片、视频、附件。

### 事务

保证一组操作具有 ACID 特性：

- 原子性；
- 一致性；
- 隔离性；
- 持久性。

### 索引

通过额外的数据结构提高查询速度，但会增加存储和写入成本。

### 数据一致性

- 强一致性；
- 最终一致性；
- 读写一致性；
- 缓存与数据库一致性。

### 数据迁移

随着系统升级修改表结构或历史数据，例如增加字段、建立索引、拆分数据。

## 9. Web 安全

### XSS

攻击者把恶意脚本注入页面。常见防护：

- 输出转义；
- 避免渲染不可信 HTML；
- CSP；
- 使用安全模板机制。

### CSRF

利用用户已有登录状态，诱导浏览器向目标网站发送请求。常见防护：

- CSRF Token；
- `SameSite` Cookie；
- 校验 Origin 或 Referer；
- 敏感操作二次确认。

### SQL 注入

输入内容被当成 SQL 执行。应使用参数化查询，避免拼接 SQL。

### 越权

- 水平越权：访问其他同级用户的数据；
- 垂直越权：普通用户执行管理员操作。

前端隐藏按钮不等于鉴权，真正的权限判断必须在服务端执行。

### 其他安全概念

- 密码摘要：使用 Argon2、bcrypt 等算法，不能明文保存密码；
- 限流：限制单位时间内的请求次数；
- 防重放：防止合法请求被复制后再次执行；
- CSP：限制页面可以加载和执行的资源；
- SRI：验证第三方静态资源是否被篡改；
- Secret 管理：密钥不能写进前端代码或提交到 Git；
- 文件上传安全：检查文件类型、大小、内容和存储位置；
- 安全响应头：如 HSTS、CSP、`X-Content-Type-Options`；
- 审计日志：记录谁在什么时间执行了什么敏感操作。

## 10. 缓存与性能

### 浏览器缓存

通过以下响应头控制：

- `Cache-Control`
- `ETag`
- `Last-Modified`

### CDN

把静态资源缓存到更接近用户的边缘节点，降低延迟和源站压力。

### 服务端缓存

缓存数据库查询、页面或接口结果。

### 性能指标

常见 Web 指标：

- TTFB：服务器开始响应的时间；
- LCP：主要内容出现的时间；
- INP：交互响应延迟；
- CLS：页面布局跳动程度。

### 常见优化

- 代码分割；
- 懒加载；
- 图片压缩；
- 虚拟列表；
- 防抖和节流；
- 减少重复请求；
- 数据库索引；
- CDN；
- 压缩传输；
- 预加载与预连接。

## 11. 架构概念

### 单体应用

前后端业务集中在一个服务中，开发部署简单，但规模扩大后可能耦合严重。

### 前后端分离

前端通过 API 与后端通信，双方可以独立开发和部署。

### 微服务

按照业务边界拆分多个独立服务，需要额外处理服务发现、调用、监控和一致性。

### BFF

Backend For Frontend，为特定前端提供聚合和适配接口。

### API 网关

统一处理：

- 请求路由；
- 认证；
- 限流；
- 日志；
- 协议转换；
- 灰度发布。

### 多租户

一套系统服务多个企业或组织，必须处理：

- 租户识别；
- 数据隔离；
- 权限隔离；
- 配置隔离；
- 资源配额。

### 领域驱动设计

围绕业务领域组织代码，常见概念包括实体、值对象、聚合、领域服务和限界上下文。

## 12. 构建、部署与运维

### 构建

把源代码转换为可部署产物，包括：

- 编译；
- 打包；
- 压缩；
- Tree Shaking；
- 环境变量注入。

### 环境

通常分为：

- 本地开发环境；
- 测试环境；
- 预发布环境；
- 生产环境。

### CI/CD

自动执行：

```text
提交代码 → 静态检查 → 测试 → 构建 → 部署
```

### 容器

使用 Docker 等工具封装应用及其运行环境。

### 反向代理

Nginx 等组件接收外部请求，再转发给内部服务，同时处理 HTTPS、压缩和负载均衡。

### 可观测性

包括：

- 日志 Logging；
- 指标 Metrics；
- 链路追踪 Tracing；
- 告警 Alerting；
- 错误监控。

### 灰度与回滚

- 灰度发布：先让部分用户使用新版本；
- 蓝绿部署：准备两套环境后切换流量；
- 金丝雀发布：逐步扩大新版本流量；
- 回滚：异常时恢复旧版本；
- Feature Flag：不重新发布代码即可开关功能。

## 13. 测试与质量

### 测试层次

- 单元测试：验证函数或组件；
- 集成测试：验证多个模块协作；
- API 测试：验证接口契约；
- E2E 测试：模拟真实用户操作；
- 性能测试：验证吞吐量和响应时间；
- 安全测试：检查注入、越权等问题。

### 静态质量检查

- 类型检查；
- Lint；
- 格式化；
- 依赖漏洞扫描；
- 代码审查。

### Mock

使用模拟接口或对象隔离外部依赖，使前后端可以并行开发和独立测试。

## 14. 用户体验与可访问性

### 响应式设计

根据手机、平板和桌面屏幕调整页面布局。

### 可访问性 A11y

让键盘用户、读屏用户和视觉障碍用户也能使用页面：

- 语义化 HTML；
- 键盘可操作；
- 合理焦点顺序；
- 足够的颜色对比度；
- 表单 Label；
- ARIA 属性。

### 页面状态

完整页面通常需要考虑：

- 默认状态；
- 加载状态；
- 空状态；
- 错误状态；
- 无权限状态；
- 禁用状态；
- 成功反馈；
- 离线状态。

## 一条典型请求的完整链路

以“登录后查看订单”为例：

```text
浏览器访问页面
  → DNS 解析域名
  → HTTPS 建立连接
  → CDN/反向代理接收请求
  → 前端资源加载
  → 用户提交账号密码
  → 后端认证用户身份
  → 创建 Session 或签发 Token
  → 浏览器保存 Cookie
  → 前端请求订单 API
  → 认证中间件识别用户
  → 鉴权模块检查订单访问权限
  → Service 执行业务规则
  → 数据访问层查询数据库
  → 服务端返回 JSON
  → 前端更新状态并渲染页面
  → 日志、指标、链路追踪记录全过程
```
