## 1. 加密基础

### 加密三大分类

```
① 对称加密（Symmetric Encryption）
   加密和解密使用同一把密钥

   明文 → [密钥加密] → 密文 → [密钥解密] → 明文

   算法：AES-256, ChaCha20, DES（已淘汰）
   优点：速度快
   缺点：密钥分发困难

② 非对称加密（Asymmetric Encryption）
   公钥加密，私钥解密（或反过来）

   明文 → [公钥加密] → 密文 → [私钥解密] → 明文

   算法：RSA, ECC, Ed25519
   优点：解决密钥分发问题
   缺点：速度慢

③ 哈希函数（Hash）
   任意长度输入 → 固定长度输出，不可逆

   明文 → [哈希函数] → 摘要（固定长度）

   算法：SHA-256, SHA-3, BLAKE3
   特点：不可逆、确定性、抗碰撞
   用途：完整性校验、密码存储、数字签名
```

### 对称 vs 非对称

| 特性 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| 密钥 | 一把密钥 | 公钥+私钥对 |
| 速度 | 快 | 慢（约慢 100-1000 倍） |
| 安全性 | 密钥泄露即不安全 | 私钥不泄露即安全 |
| 用途 | 大量数据加密 | 密钥交换、数字签名 |
| 典型算法 | AES | RSA, ECC |

### TLS 中的混合加密

```
实际 HTTPS 使用混合加密：

  ① 非对称加密协商出对称密钥（安全但慢）
  ② 后续通信用对称密钥加密（快速）

  这样兼顾了安全性和性能
```

### 哈希与数字签名

```
数字签名流程：

  发送方：
  ① 对消息计算哈希：hash = SHA256(message)
  ② 用私钥加密哈希：signature = RSA_Sign(hash, private_key)
  ③ 发送 message + signature

  接收方：
  ① 用公钥解密签名：hash1 = RSA_Verify(signature, public_key)
  ② 对消息计算哈希：hash2 = SHA256(message)
  ③ 比对 hash1 == hash2 → 验证通过

  作用：验证数据完整性和发送者身份
```

### OpenSSL 操作

```bash
# 生成 RSA 密钥对
openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -pubout -out public.pem

# 用公钥加密
echo "secret message" | openssl rsautl -encrypt -pubin -inkey public.pem -out encrypted.bin

# 用私钥解密
openssl rsautl -decrypt -inkey private.pem -in encrypted.bin

# 计算文件哈希
sha256sum file.txt
md5sum file.txt        # 不推荐，不安全

# 创建数字签名
openssl dgst -sha256 -sign private.pem -out signature.bin file.txt

# 验证签名
openssl dgst -sha256 -verify public.pem -signature signature.bin file.txt

# 生成自签证书
openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -days 365 -nodes \
  -subj "/CN=example.com"
```

## 2. TLS/SSL 深入

### TLS 握手详解（TLS 1.2）

```
客户端                                     服务器
  |                                          |
  | --- ClientHello ----------------------→  |  ① 支持的 TLS 版本、加密套件、随机数
  |                                          |
  | ←-- ServerHello -----------------------  |  ② 选择的加密套件、随机数
  | ←-- Certificate -----------------------  |  ③ 服务器证书（含公钥）
  | ←-- ServerKeyExchange ----------------  |  ④ 密钥交换参数（DH）
  | ←-- ServerHelloDone -------------------  |  ⑤ 服务器握手完成
  |                                          |
  | --- ClientKeyExchange -----------------→  |  ⑥ 客户端密钥交换参数
  | --- ChangeCipherSpec ------------------→  |  ⑦ 切换到加密
  | --- Finished (加密) -------------------→  |  ⑧ 加密验证
  |                                          |
  | ←-- ChangeCipherSpec -------------------  |  ⑨ 服务器切换到加密
  | ←-- Finished (加密) -------------------   |  ⑩ 加密验证
  |                                          |
  | ====== 加密应用数据传输 ================  |
```

### TLS 1.3 优化

```
TLS 1.2：2-RTT 握手（两次往返）
TLS 1.3：1-RTT 握手（一次往返），支持 0-RTT 恢复

改进：
  - 删除不安全的算法（RSA 密钥交换、CBC 模式等）
  - 强制使用前向安全（Ephemeral 密钥交换）
  - 合并握手步骤，减少往返
  - 加密更多握手消息（隐私保护）
```

### 前向安全（Forward Secrecy）

```
没有前向安全：
  如果私钥泄露 → 所有历史通信可被解密

有前向安全（使用 Ephemeral 密钥）：
  每次会话使用临时密钥 → 私钥泄露不影响历史通信

实现方式：
  DHE  - Diffie-Hellman Ephemeral
  ECDHE - 椭圆曲线 DH Ephemeral（更高效，推荐）
```

### 证书链验证

```
根 CA（自签名，浏览器/操作系统预装）
  |
  └── 中间 CA
        |
        └── 网站证书（example.com）

验证过程：
  ① 网站证书由中间 CA 签名 → 用中间 CA 公钥验证
  ② 中间 CA 由根 CA 签名 → 用根 CA 公钥验证
  ③ 根 CA 预装在系统中 → 信任链建立

查看证书链：
  openssl s_client -connect example.com:443 -showcerts
```

### 证书包含的信息

```
证书内容：
  - 版本（V3）
  - 序列号
  - 签名算法
  - 颁发者（Issuer）→ 中间 CA
  - 有效期（Not Before / Not After）
  - 主体（Subject）→ 域名
  - 主体公钥
  - SAN（Subject Alternative Names）→ 可覆盖的域名列表
  - CA 签名

查看证书详情：
  openssl x509 -in cert.pem -text -noout
```

### TLS 安全配置检查

```bash
# 检查网站 TLS 配置
openssl s_client -connect example.com:443 -tls1_2
openssl s_client -connect example.com:443 -tls1_3

# 检查支持的加密套件
nmap --script ssl-enum-ciphers -p 443 example.com

# 在线工具：
#   https://www.ssllabs.com/ssltest/  ← SSL Labs 评级
#   https://www.howsmyssl.com/

# 检查证书过期时间
echo | openssl s_client -connect example.com:443 2>/dev/null \
  | openssl x509 -noout -dates
```

## 3. 认证与授权

### 认证（Authentication）vs 授权（Authorization）

```
认证 = 你是谁？（Identity）
  方式：用户名密码、Token、证书、生物识别

授权 = 你能做什么？（Access）
  方式：RBAC、ABAC、ACL
```

### 常见认证方式

| 方式 | 说明 | 示例 |
|------|------|------|
| Basic Auth | 用户名密码 Base64 编码 | `Authorization: Basic dXNlcjpwYXNz` |
| Session Cookie | 服务端存储会话 | `Cookie: session=abc123` |
| Bearer Token | 无状态令牌 | `Authorization: Bearer eyJhb...` |
| JWT | 自包含令牌 | Header.Payload.Signature |
| OAuth 2.0 | 授权框架 | 第三方登录（Google/GitHub） |
| mTLS | 双向证书认证 | 客户端和服务器互相验证证书 |
| API Key | 简单密钥 | `X-API-Key: xxx` |

### JWT 详解

```
JWT 结构：Header.Payload.Signature

Header:
  {"alg": "HS256", "typ": "JWT"}     → Base64URL 编码

Payload:
  {"sub": "1234", "name": "Alice", "exp": 1700000000}  → Base64URL 编码

Signature:
  HMACSHA256(Base64(Header) + "." + Base64(Payload), secret)

完整 JWT：
  eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0IiwibmFtZSI6IkFsaWNlIn0.签名
```

```bash
# 解码 JWT（不需要密钥就能看 Header 和 Payload）
echo "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0IiwibmFtZSI6IkFsaWNlIn0.xxx" \
  | cut -d. -f2 | base64 -d 2>/dev/null | jq .

# JWT 特点：
# 优点：无状态、自包含、跨域
# 缺点：无法主动失效（除非维护黑名单）、令牌较大
```

### OAuth 2.0 授权码流程

```
① 用户 → 客户端：我要用 GitHub 登录
② 客户端 → GitHub 授权页：重定向（带 client_id + redirect_uri + scope）
③ 用户 → GitHub：同意授权
④ GitHub → 客户端：重定向回 redirect_uri（带 authorization code）
⑤ 客户端 → GitHub Token 端点：用 code 换 access_token
⑥ GitHub → 客户端：返回 access_token
⑦ 客户端 → GitHub API：用 access_token 访问用户数据

关键：authorization code 通过浏览器传递，access_token 只在服务端交换
```

## 4. 常见网络攻击与防御

### 攻击概览

```
┌─────────────────────────────────────────┐
│           网络层攻击                      │
│  DDoS / SYN Flood / ICMP Flood          │
├─────────────────────────────────────────┤
│           传输层攻击                      │
│  中间人攻击 / 会话劫持 / 端口扫描         │
├─────────────────────────────────────────┤
│           应用层攻击                      │
│  SQL注入 / XSS / CSRF / 点击劫持          │
└─────────────────────────────────────────┘
```

### DDoS 攻击

```
DDoS（Distributed Denial of Service）
分布式拒绝服务攻击：用大量请求耗尽服务器资源

类型：
  流量型：UDP Flood, ICMP Flood → 带宽耗尽
  协议型：SYN Flood → TCP 连接耗尽
  应用层：HTTP Flood → 服务器 CPU/内存耗尽

防御：
  ✓ 流量清洗（CDN/WAF）
  ✓ 限流（Rate Limiting）
  ✓ SYN Cookie（防 SYN Flood）
  ✓ 弹性扩容
  ✓ 黑洞路由（引流到黑洞丢弃）
```

### SYN Flood 攻击

```
攻击原理：
  攻击者大量发送 SYN 包但不回 ACK
  → 服务器为每个半开连接分配资源
  → 半开连接队列耗尽 → 无法服务正常请求

防御：
  ✓ SYN Cookie：不分配资源，用加密 Cookie 编码连接信息
  ✓ SYN Proxy：代理层先完成握手再转发
  ✓ 限制半开连接数

# Linux 内核参数调优
sysctl -w net.ipv4.tcp_syncookies=1      # 启用 SYN Cookie
sysctl -w net.ipv4.tcp_max_syn_backlog=65535  # 增大半连接队列
```

### 中间人攻击（MITM）

```
攻击者位于客户端和服务器之间：

  [客户端] ←──→ [攻击者] ←──→ [服务器]
                    |
              拦截/篡改/窃听

防御：
  ✓ HTTPS/TLS（证书验证防止冒充）
  ✓ HSTS（防止降级到 HTTP）
  ✓ 证书固定（Certificate Pinning）
  ✓ 使用 VPN/加密隧道

# 实验工具：mitmproxy（仅用于学习）
mitmproxy --mode regular -p 8080
# 配置浏览器代理为 127.0.0.1:8080，观察 HTTPS 流量
```

### ARP 欺骗

```
攻击者伪造 ARP 应答：
  "网关 IP 的 MAC 是攻击者的 MAC"

→ 受害者流量发给攻击者 → 中间人攻击

防御：
  ✓ 静态 ARP 绑定
  ✓ DAI（Dynamic ARP Inspection，交换机层面）
  ✓ 网络分段

# 检测 ARP 欺骗
sudo arpwatch -i eth0
```

### DNS 劫持/污染

```
DNS 劫持：DNS 服务器返回伪造的 IP
DNS 污染：在 DNS 响应到达前注入伪造响应

防御：
  ✓ DNS over HTTPS (DoH)
  ✓ DNS over TLS (DoT)
  ✓ 使用可信 DNS（8.8.8.8, 1.1.1.1）

# 使用 DoH
curl --doh-url https://dns.google/dns-query https://example.com
```

## 5. 防火墙

### iptables 四表五链

```
五链（Hook 点）：
  PREROUTING    → 数据包进入网卡后、路由前
  INPUT         → 目标是本机的数据包
  FORWARD       → 经过本机转发的数据包
  OUTPUT        → 本机发出的数据包
  POSTROUTING   → 路由后、发出网卡前

四表：
  raw       → 连接跟踪豁免
  mangle    → 修改数据包
  nat       → 地址转换
  filter    → 过滤（最常用）
```

### filter 表规则

```bash
# 查看规则
sudo iptables -L -n -v
sudo iptables -L INPUT -n --line-numbers

# 允许已建立连接和相关连接
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 允许回环接口
sudo iptables -A INPUT -i lo -j ACCEPT

# 允许 SSH（22）、HTTP（80）、HTTPS（443）
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 允许 ping
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT

# 默认策略：拒绝其他所有入站
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# 丢弃规则
sudo iptables -A INPUT -j DROP
```

### 常用防火墙操作

```bash
# 插入规则到链首
sudo iptables -I INPUT 1 -p tcp --dport 8080 -j ACCEPT

# 删除指定规则
sudo iptables -D INPUT 3    # 删除第 3 条

# 保存规则（Ubuntu）
sudo apt install iptables-persistent
sudo netfilter-persistent save

# 保存规则（CentOS）
sudo service iptables save

# 清空所有规则
sudo iptables -F

# 限制单个 IP 的连接速率
sudo iptables -A INPUT -p tcp --dport 80 -m conntrack --ctstate NEW -m recent --set
sudo iptables -A INPUT -p tcp --dport 80 -m conntrack --ctstate NEW -m recent --update --seconds 60 --hitcount 100 -j DROP
# 60 秒内超过 100 个新连接 → 丢弃
```

### ufw（Ubuntu 简化防火墙）

```bash
# 安装
sudo apt install ufw

# 基本操作
sudo ufw enable              # 启用
sudo ufw status verbose      # 查看状态
sudo ufw allow 80/tcp        # 允许 80 端口
sudo ufw allow 443/tcp       # 允许 443 端口
sudo ufw allow 22/tcp        # 允许 SSH
sudo ufw deny 3306           # 拒绝 MySQL 外部访问
sudo ufw delete allow 8080   # 删除规则

# 限制
sudo ufw limit 22            # 限制 SSH 连接速率
```

## 6. Web 安全

### OWASP Top 10 常见漏洞

| 排名 | 漏洞 | 说明 |
|------|------|------|
| 1 | 访问控制失效 | 未授权访问 |
| 2 | 加密失败 | 敏感数据明文传输 |
| 3 | 注入 | SQL/命令注入 |
| 4 | 不安全设计 | 架构层面缺陷 |
| 5 | 安全配置错误 | 默认配置、目录列出 |
| 6 | 脆弱组件 | 第三方库漏洞 |
| 7 | 认证失败 | 弱密码、会话固定 |
| 8 | 数据完整性失败 | 未验证的反序列化 |
| 9 | 日志监控不足 | 无法检测攻击 |
| 10 | SSRF | 服务端请求伪造 |

### SQL 注入

```
漏洞代码：
  SELECT * FROM users WHERE name = '" + input + "'

输入：admin' OR '1'='1
SQL：SELECT * FROM users WHERE name = 'admin' OR '1'='1'
→ 返回所有用户

防御：
  ✓ 参数化查询（Prepared Statement）
  ✓ ORM 框架
  ✓ 输入验证和转义
  ✓ 最小权限原则（数据库用户只授权必要权限）
```

### XSS（跨站脚本）

```
攻击方式：注入恶意 JavaScript 到页面

  存储型：恶意代码存入数据库 → 其他用户浏览时执行
  反射型：恶意代码在 URL 中 → 用户点击时执行
  DOM 型：前端 JS 操作 DOM 时注入

防御：
  ✓ 输出编码（HTML 转义）
  ✓ CSP（Content Security Policy）
  ✓ HttpOnly Cookie
  ✓ 输入验证

Nginx CSP 配置：
  add_header Content-Security-Policy "default-src 'self'; script-src 'self'";
```

### CSRF（跨站请求伪造）

```
攻击方式：诱导用户在已登录状态下发起非自愿请求

  用户已登录 bank.com
  → 访问恶意网站 evil.com
  → evil.com 发起 POST bank.com/transfer
  → 浏览器自动带上 bank.com 的 Cookie
  → 转账成功

防御：
  ✓ CSRF Token
  ✓ SameSite Cookie
  ✓ Referer / Origin 验证

Nginx 配置 SameSite Cookie：
  proxy_cookie_path / "/; HTTPOnly; Secure; SameSite=Strict";
```

### 安全 HTTP Headers

```nginx
server {
    # 防止点击劫持
    add_header X-Frame-Options "SAMEORIGIN" always;

    # 防止 MIME 类型嗅探
    add_header X-Content-Type-Options "nosniff" always;

    # XSS 保护
    add_header X-XSS-Protection "1; mode=block" always;

    # HSTS - 强制 HTTPS
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

    # CSP - 内容安全策略
    add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'" always;

    # Referrer 策略
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # 权限策略
    add_header Permissions-Policy "geolocation=(), microphone=()" always;
}
```

### WAF（Web 应用防火墙）

```
WAF 在 HTTP 层面检测和拦截攻击

功能：
  - 拦截 SQL 注入、XSS、CSRF
  - 限流和 DDoS 防护
  - 虚拟补丁
  - CC 攻击防护

常见 WAF：
  - Cloudflare WAF（云服务）
  - ModSecurity（开源，Nginx 可集成）
  - AWS WAF
  - 阿里云 WAF
```

```bash
# 安装 ModSecurity for Nginx
sudo apt install libmodsecurity3 libnginx-mod-http-modsecurity

# 启用 ModSecurity
# 在 nginx.conf 中添加：
```

## 7. 网络性能优化

### 性能优化总览

```
前端优化：
  ├── 减少 HTTP 请求（合并文件、雪碧图、内联）
  ├── 压缩资源（Gzip/Brotli、图片压缩）
  ├── 浏览器缓存
  ├── CDN 加速
  ├── 懒加载 / 预加载
  └── HTTP/2 多路复用

网络优化：
  ├── 减少 DNS 查询（dns-prefetch）
  ├── 减少重定向
  ├── 使用 HTTP/2 或 HTTP/3
  ├── TCP 连接复用（Keep-Alive）
  └── 就近部署（CDN 边缘节点）

后端优化：
  ├── 数据库索引
  ├── 缓存（Redis/Memcached）
  ├── 异步处理（消息队列）
  ├── 连接池
  └── 水平扩容
```

### HTTP 性能分析


### TCP 优化参数

```bash
# /etc/sysctl.conf

# 增大 TCP 缓冲区
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216

# 增大连接队列
net.core.somaxconn = 65535
net.ipv4.tcp_max_syn_backlog = 65535

# 启用 SYN Cookie（防 SYN Flood）
net.ipv4.tcp_syncookies = 1

# TIME_WAIT 优化
net.ipv4.tcp_tw_reuse = 1        # 允许复用 TIME_WAIT 连接
net.ipv4.tcp_max_tw_buckets = 5000

# Keep-Alive 优化
net.ipv4.tcp_keepalive_time = 600
net.ipv4.tcp_keepalive_intvl = 30
net.ipv4.tcp_keepalive_probes = 3

# 启用 TCP Fast Open
net.ipv4.tcp_fastopen = 3

# 启用 BBR 拥塞控制（替代默认 CUBIC）
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr

# 应用配置
sudo sysctl -p
```

### HTTP/2 与 HTTP/3

```
HTTP/1.1 问题：
  - 队头阻塞：一个慢请求阻塞后续请求
  - 头部未压缩
  - 需要多开连接

HTTP/2 改进：
  - 多路复用：一个连接上并行多个请求
  - 头部压缩（HPACK）
  - 服务端推送
  - 二进制分帧

HTTP/3 改进：
  - 基于 QUIC（UDP），不依赖 TCP
  - 解决队头阻塞（各流独立）
  - 0-RTT 连接恢复
  - 连接迁移（IP 变化不断连）

Nginx 启用 HTTP/2：
  listen 443 ssl http2;
```

### 缓存策略

```
三级缓存架构：

  浏览器缓存 → CDN 缓存 → 服务器缓存（Nginx proxy_cache）→ 应用缓存（Redis）

强缓存（不发请求）：
  Cache-Control: max-age=31536000, immutable
  → 文件名带 hash（app.a1b2c3.js），一年强缓存

协商缓存（验证是否变化）：
  ETag / If-None-Match → 304 Not Modified
  Last-Modified / If-Modified-Since → 304

不缓存：
  Cache-Control: no-store
  → API 响应、敏感数据
```

### 练习5：综合安全加固

```bash
# 对一个 Nginx 服务器进行安全加固

# ① 系统层面
# 更新系统
sudo apt update && sudo apt upgrade

# ② SSH 安全
sudo tee -a /etc/ssh/sshd_config << 'EOF'
Port 2222                    # 修改默认端口
PermitRootLogin no           # 禁止 root 登录
PasswordAuthentication no    # 禁用密码登录（使用密钥）
MaxAuthTries 3               # 最大尝试次数
EOF
sudo systemctl restart sshd

# ③ 防火墙
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 2222/tcp      # 新 SSH 端口
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

# ④ Nginx 安全配置
sudo tee /etc/nginx/conf.d/hardening.conf << 'EOF'
server {
    # 隐藏 Nginx 版本号
    server_tokens off;

    # 安全 Header
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Strict-Transport-Security "max-age=31536000" always;

    # 限制请求体大小
    client_max_body_size 1m;

    # 禁止访问敏感文件
    location ~ /\. {
        deny all;
    }
    location ~* \.(env|git|svn) {
        deny all;
    }

    # 限流
    limit_req_zone $binary_remote_addr zone=general:10m rate=10r/s;
    limit_req zone=general burst=20 nodelay;
}
EOF

# ⑤ 验证
sudo nginx -t && sudo nginx -s reload
curl -I http://localhost
# 确认 Server header 不显示版本号
# 确认安全 Header 已添加
```
