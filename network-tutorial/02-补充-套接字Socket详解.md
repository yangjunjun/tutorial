# 补充 - 套接字（Socket）详解

> 针对 `02-TCP-IP基础与抓包分析.md` 中「端口与套接字」相关概念的深入说明。

---

## 1. 套接字是什么

**一句话**：套接字是操作系统提供给应用程序访问网络的 **API 接口**，是"网络通信的端点"。

应用程序不直接操作网卡、不直接构造 TCP/UDP 报文——这些底层工作交给操作系统内核。程序只需要调用 socket API，内核帮你完成一切。

---

## 2. 生活类比

### 打电话

```
你拿起电话        → 创建 socket（socket()）
拨号到对方号码     → 发起连接（connect，目标 IP + 端口）
对方接听          → 接受连接（accept）
双方通话          → 收发数据（read / write）
挂断              → 关闭连接（close）
```

### 寄信

```
信封上的地址  = IP 地址（找到哪台机器）
门牌号        = 端口号  （找到哪个程序）
IP + 端口     = 套接字地址（精确到一个进程）
```

---

## 3. 本质

```
套接字 = {IP 地址 : 端口号}  →  唯一标识一个网络通信端点

一条 TCP 连接由两个套接字唯一确定（四元组）：
  连接 = {客户端 IP : 客户端端口, 服务器 IP : 服务器端口}
```

> 这意味着：同一台机器上的同一个端口，可以同时维持多条 TCP 连接——因为每条连接的四元组不同（客户端 IP 或端口不同）。

---

## 4. 在 Linux 中：万物皆文件

套接字在 Linux 里**就是一个文件描述符（fd）**，和普通文件、管道、终端设备一样统一管理：

```c
// 创建套接字 → 得到一个 fd
int sockfd = socket(AF_INET, SOCK_STREAM, 0);

// 之后对它的操作就像操作文件一样
write(sockfd, data, len);   // 发送数据
read(sockfd, buf, len);     // 接收数据
close(sockfd);              // 关闭连接
```

```
进程
 │
 │  fd = 3 ────→ [socket 对象] ────→ 内核网络协议栈 ────→ 网卡
 │
 │  fd = 4 ────→ [普通文件]   ────→ 磁盘
 │
 │  fd = 0 ────→ [stdin]      ────→ 终端
```

---

## 5. 套接字类型

| 类型 | 说明 | 对应协议 | 特点 |
|------|------|---------|------|
| `SOCK_STREAM` | 流式套接字 | TCP | 面向连接、可靠有序、按字节流传输 |
| `SOCK_DGRAM` | 数据报套接字 | UDP | 无连接、不可靠、按消息传输、有边界 |
| `SOCK_RAW` | 原始套接字 | 自定义 / IP 层 | 可绕过传输层直接构造 IP 包，用于抓包、自定义协议 |

### TCP vs UDP 套接字的区别

```
TCP（SOCK_STREAM）：像打电话
  建立连接 → 通话 → 挂断
  数据是连续的字节流，没有边界

UDP（SOCK_DGRAM）：像发短信
  不建立连接，直接发
  每条消息独立，有明确边界
  可能丢失、乱序
```

## 6. 服务器端经典流程

```
socket()    → 创建套接字（得到 fd）
    │
bind()      → 绑定 IP + 端口（告诉系统："这个端口归我了"）
    │
listen()    → 开始监听，等待客户端连接
    │           ├── 内核维护两个队列：
    │           │   ① 半连接队列（SYN Queue）：收到 SYN，等第三次握手
    │           │   ② 全连接队列（Accept Queue）：握手完成，等 accept 取走
    │
accept()    → 从全连接队列取出一个已完成连接
    │           └── 返回一个新的 fd（专门和这个客户端通信）
    │           └── 原来的监听 fd 继续等待其他客户端
    │
read/write  → 收发数据
    │
close()     → 关闭连接
```

### 为什么 accept 要返回新的 fd？

```
监听 fd（如 fd=3）  → 负责接客，一直守在门口
    │
accept → fd=4      → 专门服务客户端 A
accept → fd=5      → 专门服务客户端 B
accept → fd=6      → 专门服务客户端 C
```

一个监听套接字可以派生出无数个连接套接字，互不干扰。

---

## 7. 客户端经典流程

```
socket()    → 创建套接字（得到 fd）
    │
connect()   → 向服务器发起连接（携带目标 IP + 端口）
    │           └── 内核自动完成三次握手
    │           └── 绑定源 IP + 随机源端口（不需要手动 bind）
    │
read/write  → 收发数据
    │
close()     → 关闭连接
```

---

## 8. 服务器 vs 客户端流程对比

```
    服务器                              客户端
                ┌─ socket() ─┐
                │             │
    bind()      │             │  （内核自动绑定源端口）
                │             │
    listen()    │             │
                │             │
    accept() ←──┤             ├──→ connect()
                │             │     （三次握手在此完成）
                │             │
    read() ←────┼─────────────┼────→ write()
    write() ───→┼─────────────┼←──── read()
                │             │
    close()     │             │  close()
                └─────────────┘
```

## 9. 查看系统中的套接字

```bash
# 查看所有 TCP 套接字（推荐 ss）
ss -tnp

# 输出示例：
# State   Local Address:Port    Peer Address:Port    Process
# ESTAB   192.168.1.5:54321    93.184.216.34:443    curl
# LISTEN  0.0.0.0:80           0.0.0.0:*            nginx
#         ↑ 本地套接字           ↑ 远程套接字

# 选项含义：
# -t  TCP
# -n  不解析域名（显示 IP）
# -p  显示进程信息

# 老命令（逐渐被 ss 替代）
netstat -tnp

# 只看监听套接字
ss -tlnp

# 查看某个端口被谁占用
ss -tlnp | grep :8080
lsof -i :8080
```

## 10. 常见系统调用速查

| 系统调用 | 服务器 | 客户端 | 说明 |
|---------|--------|--------|------|
| `socket()` | ✅ | ✅ | 创建套接字，返回 fd |
| `bind()` | ✅ | 可选 | 绑定地址（客户端通常省略，内核自动分配） |
| `listen()` | ✅ | ❌ | 标记为被动套接字，开始等待连接 |
| `accept()` | ✅ | ❌ | 取出已完成连接，返回新 fd |
| `connect()` | ❌ | ✅ | 主动发起连接（触发三次握手） |
| `read()` / `recv()` | ✅ | ✅ | 读取数据 |
| `write()` / `send()` | ✅ | ✅ | 发送数据 |
| `close()` | ✅ | ✅ | 关闭连接（触发四次挥手） |
| `shutdown()` | ✅ | ✅ | 半关闭（只关读 / 只关写 / 都关） |

---

## 11. 一句话总结

套接字就是**应用程序和网络协议栈之间的桥梁**——程序通过它收发数据，操作系统通过它知道数据该交给哪个进程。
