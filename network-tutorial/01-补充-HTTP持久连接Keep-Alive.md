# 补充 - HTTP/1.1 持久连接（Keep-Alive）

> 针对 `01-HTTP协议与curl基础.md` 中「HTTP/1.1 → 持久连接（Keep-Alive）」一条的深入说明。

---

## 1. 解决什么问题

**HTTP/1.0 的默认行为**：每个请求都需要单独建立一条 TCP 连接，请求完就断开。

```
请求1: TCP握手 → 请求 → 响应 → TCP断开
请求2: TCP握手 → 请求 → 响应 → TCP断开
请求3: TCP握手 → 请求 → 响应 → TCP断开
```

问题：

- 每次都经历 TCP 三次握手 + 四次挥手，**延迟高**
- TCP 拥塞窗口每次都从零开始爬升，**吞吐量低**
- 大量 `TIME_WAIT` 状态占用端口资源

---

## 2. HTTP/1.1 的做法

**默认开启**持久连接，TCP 连接建立后不立即关闭，多个请求/响应可复用同一条连接：

```
TCP握手 → 请求1 → 响应1 → 请求2 → 响应2 → 请求3 → 响应3 → TCP断开
         └─────────────── 连接保持 ──────────────┘
```

---

## 3. 控制头部

```
Connection: keep-alive          # 客户端请求保持连接（HTTP/1.1 默认，可省略）
Connection: close               # 明确要求关闭连接
Keep-Alive: timeout=5, max=100  # 服务端建议：空闲5秒后关闭，最多复用100次
```

---

## 4. 关键机制

| 机制 | 说明 |
|------|------|
| 连接复用 | 一条 TCP 连接可串行发送多个请求 |
| 分隔消息 | 靠 `Content-Length` 或 `Transfer-Encoding: chunked` 判断每个响应的边界 |
| 空闲超时 | 服务端通常设空闲超时（如 5~60s），超时后主动关闭 |
| 请求上限 | 可限制单连接最大请求数，防止长期占用 |

---

## 5. 局限：队头阻塞（HOL Blocking）

持久连接下多个请求是**串行**的，必须等前一个响应返回才能发下一个：

```
请求1（慢）→ 响应1 ────┐
                       请求2 → 响应2 ────┐
                                          请求3 → 响应3
```

请求1 慢会阻塞后续所有请求。浏览器为缓解此问题，通常对同一域名**并行开 6 条**持久连接。

---

## 6. 对比一览

| | HTTP/1.0 | HTTP/1.1 |
|---|---------|----------|
| 默认行为 | 每请求一连接 | 持久连接 |
| 开启方式 | `Connection: keep-alive`（需手动） | 默认开启，`Connection: close` 才关闭 |
| 管道化 | 不支持 | 支持（但几乎没人用，因中间代理兼容性差） |
