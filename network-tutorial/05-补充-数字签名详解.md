# 补充 - 数字签名详解

> 针对 `05-网络安全与性能优化.md` 中「加密基础 / TLS/SSL」相关概念的深入说明。

---

## 1. 一句话

数字签名 = **用发送方的私钥对消息摘要加密，附带在消息后面，让接收方验证消息确实来自发送方且未被篡改。**

---

## 2. 核心流程

### 签名（发送方）

```
原始消息 ──→ Hash 函数 ──→ 消息摘要（固定长度，如 256bit）
                                │
                  用发送方私钥加密
                                ↓
                          数字签名
                                │
  发送内容 = [原始消息] + [数字签名]
```

### 验签（接收方）

```
收到 [原始消息] + [数字签名]
         │              │
         │              │ 用发送方公钥解密 → 得到摘要 A
         ↓
    Hash 函数 → 得到摘要 B
         │
    比较 摘要 A == 摘要 B？
         │
    相等 → 验签通过 ✅（消息确实来自对方，且未被篡改）
    不等 → 验签失败 ❌（被篡改或不是对方发的）
```

---

## 3. 为什么不能直接对整个消息加密

- 消息可能很大，非对称加密（RSA）极慢
- Hash 把任意长度压缩成固定长度（如 SHA-256 → 256bit），只需加密摘要 → **快**

---

## 4. 数字签名解决了什么问题

| 问题 | 如何解决 |
|------|---------|
| **身份认证**（你是谁） | 只有私钥持有者才能生成合法签名，公钥人人可验 |
| **完整性**（消息被动过吗） | 消息被改一个字节，Hash 结果完全不同，验签失败 |
| **不可否认**（你不能赖账） | 私钥只有你有，签了名就赖不掉 |

---

## 5. 加密 vs 签名：方向相反

```
加密（保密）：
  公钥加密 → 私钥解密
  目的：别人看不到内容

签名（真实性 + 完整性）：
  私钥签名 → 公钥验签
  目的：别人不能伪造
```

---

## 6. HTTPS / TLS 中的应用

```
TLS 握手时，服务器发送证书：

  证书内容 = [网站信息 + 公钥 + 有效期 + ...]
                                         │
                    CA 机构用 CA 的私钥签名
                                         ↓
                              证书 = [证书内容] + [CA 的数字签名]

浏览器验证：
  用内置的 CA 公钥验签 → 确认证书确实由 CA 签发，没被篡改
  → 信任证书中的公钥 → 后续用它加密通信
```

---

## 7. 类比

| 传统签名（手写） | 数字签名 |
|----------------|---------|
| 你在合同上签字 | 你用私钥"签字" |
| 别人对比笔迹确认是你签的 | 别人用你的公钥验证 |
| 可伪造 | 不可伪造（私钥只有你有） |
| 不能验证内容是否被改 | 能验证内容完整性（Hash） |

---

## 8. 常见签名算法

| 算法 | 说明 |
|------|------|
| **RSA-SHA256** | 用 RSA 私钥对 SHA-256 摘要加密（最常见） |
| **ECDSA** | 椭圆曲线数字签名，更短的密钥达到同等安全性，TLS 1.3 推荐 |
| **Ed25519** | EdDSA 曲线，速度快、防侧信道攻击，现代首选 |
| **DSA** | 数字签名算法（仅签名，不能加密），已逐渐被淘汰 |

---

## 9. 一句话总结

数字签名就是**用私钥"盖章"、用公钥"验真"**——保证消息来自谁、没被改过、签了就赖不掉。
